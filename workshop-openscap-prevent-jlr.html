Layer 1 — Image Builder / Kickstart

Born Hardened

Compliance starts before the first login. Bake a security profile into the OS image at build time — the system is compliant from the moment it boots.

Kickstart — RHEL 7, 8, 9, 10

The %addon com_redhat_oscap Kickstart directive has worked since RHEL 7. Select a compliance profile and the installer enforces partitioning, password policy, SELinux mode, and service hardening before first boot. RHEL 9 also had a GUI spoke in Anaconda; RHEL 10 dropped the spoke but the Kickstart path is unchanged. This is the production workflow — compliance baked into every build, every time, no human clicking through an installer.

# Kickstart — works on RHEL 7 through 10
%addon com_redhat_oscap
  content-type = scap-security-guide
  profile = xccdf_org.ssgproject.content_profile_hipaa
%end

Image Builder — Golden Images in a Pipeline

# Build a HIPAA-hardened RHEL 10 image
composer-cli blueprints push rhel10-hipaa.toml
composer-cli compose start rhel10-hipaa qcow2

Image Builder takes it further — build compliant golden images in a CI pipeline. Every VM, every cloud instance, every edge device boots from the same hardened baseline. No drift from day one.

Layer 2 — CLI

The Scanner in the Box

Every RHEL subscription includes OpenSCAP and the SCAP Security Guide. More than 15 compliance profiles — HIPAA, DISA STIG, CIS Level 1 & 2, PCI-DSS, NIST 800-53, NIST 800-171. No additional purchase required.

Install

sudo dnf install -y openscap-scanner scap-security-guide

List available profiles

oscap info /usr/share/xml/scap/ssg/content/ssg-rhel9-ds.xml

Run a HIPAA scan

sudo oscap xccdf eval \
  --profile xccdf_org.ssgproject.content_profile_hipaa \
  --results /tmp/hipaa-results.xml \
  --report /tmp/hipaa-report.html \
  /usr/share/xml/scap/ssg/content/ssg-rhel9-ds.xml

SHOW

Open /tmp/hipaa-report.html in a browser. Every rule — pass or fail — with severity, description, and remediation guidance. This is audit evidence.

Generate an Ansible remediation playbook

sudo oscap xccdf generate fix \
  --fix-type ansible \
  --profile xccdf_org.ssgproject.content_profile_hipaa \
  --output /tmp/hipaa-remediate.yml \
  /usr/share/xml/scap/ssg/content/ssg-rhel9-ds.xml

SAY

"You just scanned a system against HIPAA, generated an HTML report you can hand to an auditor, and generated an Ansible playbook that fixes every failure — in three commands. This ships free with your RHEL subscription."

JLR COUNTER

Layer 3 — Red Hat Insights / Lightspeed Compliance

Fleet-Wide Visibility

One dashboard. Every host. Every policy. Every score. No infrastructure to run — it's in your RHEL subscription.

How it works

  1. Register hosts with insights-client --register
  2. Create a compliance policy at console.redhat.com → Security → Compliance
  3. Select a profile (HIPAA, STIG, CIS, PCI-DSS)
  4. Assign systems to the policy
  5. Hosts run insights-client --compliance (scheduled or on-demand)
  6. Results appear in the cloud dashboard — scores, failures, trends

SHOW

Navigate to console.redhat.com → Security → Compliance → SCAP Policies. Create a new policy. Select HIPAA. Assign hosts. Show the compliance score dashboard.

Key differentiator: The compliance service correlates with Insights Advisor (configuration risks), Vulnerability (CVE exposure), and Patch (available errata). One console shows compliance posture, security vulnerabilities, and patch status together. No separate tool.

SAY

"This is where the security team lives. You're not SSHing into boxes to run scans. You're looking at a dashboard that tells you: 14 out of 200 hosts failed the HIPAA password-complexity rule. Click. Here they are. Click. Here's the remediation. That's the difference between knowing you have a problem and finding it after the breach."

Layer 4 — Ansible Automation Platform

Compliance as Code

Scanning one host is a demo. Scanning 10,000 hosts on a schedule and auto-remediating failures — that's Ansible.

Deploy SCAP scanning fleet-wide

The theforeman.foreman_scap_client Ansible role installs the SCAP client, configures scan policies, and schedules scans on every host in a host group. One playbook. Entire fleet.

# Deploy SCAP client to all RHEL hosts
- name: Deploy OpenSCAP compliance scanning
  hosts: rhel_servers
  roles:
    - role: theforeman.foreman_scap_client
      vars:
        foreman_scap_client_server: satellite.example.com
        foreman_scap_client_port: 9090
        foreman_scap_client_policies:
          - id: 1
            profile: hipaa

Auto-remediate from scan results

# Run the remediation playbook generated by oscap
- name: Remediate HIPAA failures
  hosts: failed_hipaa
  become: true
  tasks:
    - ansible.builtin.include_tasks: hipaa-remediate.yml

In AAP Controller

SHOW

AAP Controller → Templates → create a Job Template for the SCAP deployment playbook. Set a Schedule (weekly). Assign to an Inventory that pulls from Satellite. Every new host gets scanned automatically.

SAY

"Here's where it gets serious. You're not asking people to remember to scan. You're not hoping someone runs a script. Ansible deploys the scanner, schedules the scans, collects the results, and — if you want — auto-remediates the failures. Compliance isn't a quarterly audit anymore. It's a continuous loop."

Layer 5 — Red Hat Satellite

The On-Prem Nerve Center

Satellite is where compliance policy meets content management. Upload SCAP content, create policies, assign them to host groups, schedule scans, and view compliance dashboards — all from one UI. Nothing leaves your network.

Enable OpenSCAP

# On the Satellite server
satellite-installer --enable-foreman-plugin-openscap

# Upload default SCAP content
hammer scap-content bulk-upload --type default

Create a compliance policy

CLICK

Satellite Web UI → Hosts → Compliance → Policies → New Policy

  1. Deployment method: Ansible (or Puppet or Manual)
  2. Name: "HIPAA — Production RHEL 9"
  3. SCAP Content: Red Hat rhel9-default content
  4. XCCDF Profile: HIPAA
  5. Tailoring File: (optional — customize which rules apply)
  6. Schedule: Weekly, Sunday 02:00
  7. Host Groups: assign your target groups

View compliance dashboard

CLICK

Hosts → Compliance → Policies → select policy → Dashboard. Shows: compliant count, non-compliant count, not yet scanned. Click any host for the full rule-by-rule breakdown.

View individual host compliance

CLICK

Hosts → All Hosts → click a host → Compliance tab. Shows every policy assigned to this host, last scan date, compliance score, and the full SCAP report.

SAY

"This is what Ken's been looking for. One screen that says: here are my 200 RHEL hosts, here's which ones are compliant with HIPAA, here's which ones failed, here's exactly what they failed on. No SSH. No scripts. No spreadsheets. And it's on-prem — nothing leaves your network."

Kill chain step 6: Satellite + OpenSCAP detects configuration drift within the scan cycle. A webshell that modifies system files, opens new ports, or changes SELinux booleans would trigger compliance failures on the next scan. The dashboard goes red. You see it before the attacker finishes.

Layer 6 — The Full Loop

Continuous Compliance

Each layer reinforces the others. The system is born hardened, continuously scanned, centrally managed, automatically remediated, and auditably reported.

The Loop

  1. Build: Image Builder bakes STIG/HIPAA into the golden image
  2. Deploy: Satellite provisions from the golden image
  3. Scan: AAP deploys SCAP client, schedules weekly scans
  4. Report: Results flow to Satellite dashboard + Insights console
  5. Remediate: AAP auto-fixes failures or generates tickets
  6. Re-scan: Next cycle validates the fix
  7. Prove: Auditor gets the HTML report. Done.
